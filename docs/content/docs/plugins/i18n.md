---
title: "Error localization"
description: "Translate stable typed API error messages per request while preserving status and error code."
---

The i18n plugin replaces the `message` of typed authentication errors using the request's detected locale. HTTP status and stable error `code` remain unchanged, so clients can branch on codes independently of display language.

## Install and register

Import `github.com/pers0na2dev/single-auth/plugins/i18n`. `Translations` must contain at least one locale or `singleauth.New` fails. Use `NewFactory` when `DetectionSession` is present so the plugin can lazily resolve the root session; header, cookie, callback, and already-attached session state also work with standalone `New`.

```go
package main

import (
    "log"
    "net/http"
    "os"

    singleauth "github.com/pers0na2dev/single-auth"
    "github.com/pers0na2dev/single-auth/plugins/i18n"
)

func main() {
    auth, err := singleauth.New(singleauth.Options{
        BaseURL: "http://localhost:8080",
        Secret:  os.Getenv("SINGLE_AUTH_SECRET"),
        PluginFactories: []singleauth.PluginFactory{
            i18n.NewFactory(i18n.Options{
                DefaultLocale: "en",
                Detection: []i18n.LocaleDetectionStrategy{
                    i18n.DetectionHeader,
                    i18n.DetectionCookie,
                },
                Translations: map[string]i18n.TranslationDictionary{
                    "de": {"INVALID_EMAIL_OR_PASSWORD": "E-Mail oder Passwort ist ungültig"},
                },
            }),
        },
    })
    if err != nil {
        log.Fatal(err)
    }
    log.Fatal(http.ListenAndServe(":8080", auth))
}
```

Factory order controls after-hook order. Register localization after plugins whose typed errors should reach it in their final form, and before any later after-hook that intentionally rewrites localized error bodies.

## Translation dictionaries

The outer map key is the locale and each dictionary maps a stable error code to a display message:

```go
Translations: map[string]i18n.TranslationDictionary{
    "en": {
        "INVALID_EMAIL_OR_PASSWORD": "Invalid email or password",
        "USER_NOT_FOUND":            "User not found",
    },
    "de": {
        "INVALID_EMAIL_OR_PASSWORD": "E-Mail oder Passwort ist ungültig",
        "USER_NOT_FOUND":            "Benutzer nicht gefunden",
    },
},
```

Keys are exact and case-sensitive. Populate dictionaries from the codes your installed root and plugins can return; see [Error codes](../reference/error-codes.md). A missing code or an empty translated string leaves the original response unchanged.

When a translation exists, an error such as:

```json
{"code":"INVALID_EMAIL_OR_PASSWORD","message":"Invalid email or password"}
```

becomes:

```json
{
  "code":"INVALID_EMAIL_OR_PASSWORD",
  "message":"E-Mail oder Passwort ist ungültig",
  "originalMessage":"Invalid email or password"
}
```

The translated wire body contains `code`, `message`, and `originalMessage`. Do not depend on arbitrary extra fields from a prior custom error body surviving this rewrite. Successful responses, untyped errors, undecodable error bodies, errors without a string `code`, and errors without a non-empty matching translation are not changed.

## Locale detection

Strategies run in the configured order. The first non-empty locale that is an exact key in `Translations` wins; otherwise the plugin uses `DefaultLocale`.

| Strategy | Source and behavior |
| --- | --- |
| `i18n.DetectionHeader` | Parses combined `Accept-Language`, sorts by `q`, and reduces a regional tag such as `fr-CA` to base locale `fr` |
| `i18n.DetectionCookie` | Reads `LocaleCookie` from the combined request `Cookie` header |
| `i18n.DetectionSession` | Reads `UserLocaleField` from attached session state, or lazily performs an optional root session resolution with `NewFactory` |
| `i18n.DetectionCallback` | Calls `GetLocale` with the live `*engine.Context`; skipped when the callback is nil |

Example priority that prefers an authenticated profile, then an explicit cookie, then browser language:

```go
Detection: []i18n.LocaleDetectionStrategy{
    i18n.DetectionSession,
    i18n.DetectionCookie,
    i18n.DetectionHeader,
},
UserLocaleField: "locale",
LocaleCookie:    "locale",
```

Header parsing follows the frozen compatibility behavior rather than a full locale negotiation library: it keeps only the substring before the first `-`, locale matching is case-sensitive, wildcard entries are useful only if `"*"` is an actual translation key, and unavailable languages fall through. Use simple lowercase base-language dictionary keys unless a custom callback performs richer negotiation.

`GetLocale` runs only when `DetectionCallback` is listed. It also runs for direct API calls, including headerless calls, and can inspect `ctx.IsDirect()`, headers, route, or request-scoped values. Return an unavailable/empty locale to continue to the next strategy; return an error to propagate a hook failure. The callback may be invoked concurrently and must not mutate shared request state unsafely.

## Options and defaults

| Option | Default | Behavior |
| --- | --- | --- |
| `Translations` | Required, no default | At least one locale dictionary; options are deep-snapshotted at construction |
| `DefaultLocale` | `en` | Used when no configured strategy finds an available locale; it need not exist in `Translations`, in which case no translation is found |
| `Detection` | nil, interpreted as header-only | Ordered strategies; explicit empty slice skips detection and uses the default locale |
| `LocaleCookie` | `locale` | Cookie name read by `DetectionCookie` |
| `UserLocaleField` | `locale` | Canonical session-user field read by `DetectionSession` |
| `GetLocale` | nil | Request-aware resolver used by `DetectionCallback` |

Unknown detection strategy values are skipped. Configuration slices and translation maps are copied, so changing the original maps after construction does not hot-reload messages; build a new auth instance to update them.

## Endpoints and storage

The plugin contributes no route, model, cookie write, migration, or bound service. It is an after-hook over every registered endpoint.

Translation applies consistently to typed errors returned through `net/http`, direct `fasthttp`, Fiber, and `auth.API()`. A direct caller receives the same status/body in `DirectResult.Response`; its Go error remains typed and should still be matched by code rather than localized text.

`DetectionSession` does not add a locale field to the user model. Declare that field in the root schema or another plugin, make it available in the session's user projection, and migrate it separately. Without a string value, detection falls through.

The plugin has no replay or persistence behavior. Its immutable dictionaries are safe for concurrent reads. Concurrency and latency of `GetLocale` and optional session resolution remain application/root-runtime concerns.

## Security and troubleshooting

- Treat header and cookie locales as untrusted presentation preferences, never authorization or tenancy inputs.
- Keep stable codes stable across locales. Client logic should never branch on translated `message` or `originalMessage`.
- `originalMessage` is deliberately returned whenever a translation is applied. Do not place secrets or internal diagnostics in public API error messages.
- If the original English message remains, check the exact error code, exact locale key, non-empty translation, strategy order, and whether the error is a typed `contract.APIError`.
- `Accept-Language: fr-CA` selects a `fr` dictionary, not a `fr-CA` dictionary, under the built-in parser. Use `GetLocale` if region-specific translations are required.
- Session detection may add a storage/secondary-store lookup on an error path. Put cheaper header/cookie strategies first when profile locale is not authoritative.
- An error returned by `GetLocale` or lazy session resolution is not swallowed. Keep locale lookup reliable and use fallback return values for recoverable misses.
